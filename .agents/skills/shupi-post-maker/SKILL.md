# 树皮图文自动排版

本 Skill 使用仓库中的 `app.js` 绘图逻辑和 `scripts/render.mjs` 命令行渲染器。目标是把用户文案排成可发布的逐页图片，同时保留可在 `index.html` 工作台继续修改的项目 JSON。

## 工作流

1. 读取用户文案、头像、截图与品牌要求。沿用用户已提供的昵称、@账号、高亮颜色和蓝色标识偏好；未指定高亮颜色时使用默认浅粉色。缺少头像或截图时先留空，或使用合适的内置示意图，不凭空编造截图内容。
2. 每页只讲一个要点。把长段落拆成多页，并为每页写简短标题、正文、素材形式。封面标题优先控制在一至两行，确保手机缩略图里仍能看清核心信息。正文按语义停顿主动用换行分成易读的短行，尽量让一个动作或结论完整落在一行；不要只依赖画布自动折行，也不要靠空白行填满页面。兼顾文字与下方素材的占比，避免高亮短语被折成两截或留下过大的空白；配图页检查图片是否充分占用剩余空间。用户要求保留原文时，只调整换行，不擅自改写。高亮语句用 `==文字==` 包住；只需黑色粗体时用 `**文字**`，不要误做成黑色底。项目格式见 `examples/post-project.json`。
3. 生成项目 JSON。每页可写 `highlightColor`，使用 `#RRGGBB` 格式；不写时为 `#fce1ed`。`visual` 可选 `tool`、`steps`、`skill`、`image`、`none`；使用 `image` 时填写图片路径或 data URL。若一页要在正文中间加第二张图，在 `body` 的插入点写 `[[中间图片]]`，用 `middleImage` 指向图片，原有 `image` 仍是页底配图。两张图分别用 `middleImageFit` 和 `imageFit` 选 `"cover-top"`、`"cover-center"` 或默认的 `"contain"`；文字和双图必须在同页安全区域内保持可读，空间不够时应建议拆页。上传图片直接呈现，不附加素材标题或外框。路径相对项目 JSON 所在目录解析。头像路径同理。
4. 在仓库根目录运行：`node scripts/render.mjs <项目.json> <输出目录>`。需要 Node.js 22+ 和本机 Chrome 或 Chromium；如果浏览器不在常见位置，设置 `CHROME_PATH`。
5. 逐页检查输出 PNG 的文字、头像、重点高亮、素材图与页数，重点看语义断行、意外折行、高亮是否完整、文字与配图之间及页底的留白。正文拥挤、溢出或留白失衡时，先调整分行和句长，再按需要拆页或调整素材；复查后交付 PNG 和可编辑项目 JSON。

用户创作的文案、项目 JSON、截图、头像和生成图片默认保存在本地，不加入公开仓库。只有用户明确要求公开具体素材时才纳入提交。

用户要求手动修改时，指向仓库的 `index.html` 工作台，导入同一个项目 JSON 即可继续编辑。不要在内容中虚构已上传 GitHub 的地址或发布效果。
